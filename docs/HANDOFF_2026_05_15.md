## 必须应用的 Gemini 修复(尚未编码,新机器上手动做)

在 `tools/tier_llm_factory.py` 的 `_GeminiTierClient.__init__` 里,
google-genai SDK 默认用复用连接池。**需要换成 max_keepalive=0**,
让每次 call 用完立即关 socket。

**当前未修**,因为修这个需要 monkey-patch google-genai SDK 的内部 httpx
实例,确切代码路径要现场调试。两个候选写法:

### 写法 A · 直接调 http_options(如果新版 SDK 支持)

```python
from google import genai
self._client = genai.Client(
    http_options={
        'timeout': 45.0,
        # 如下选项需要 google-genai >= 1.x.x 才支持
        # 'transport': httpx.AsyncHTTPTransport(
        #     limits=httpx.Limits(max_keepalive_connections=0)
        # )
    }
)
```

### 写法 B · 手动替换内部 httpx client(不优雅但保险)

```python
import httpx
self._client = genai.Client()
# 用我们自己的 httpx client 替换内部那个 — 路径可能因 SDK 版本而变
self._client.aio._api_client._async_httpx_client = httpx.AsyncClient(
    limits=httpx.Limits(max_connections=200, max_keepalive_connections=0),
    timeout=httpx.Timeout(45.0, read=45.0, connect=10.0, write=10.0),
)
```

**新机器上跑前**:用 `pip show google-genai` 看版本,看官方 docs 哪种写法
对得上。

### 同时也加 per-day checkpoint(可选但强烈推荐)

在 `synthetic_socio_wind_tunnel/orchestrator/multi_day.py` 的 `on_day_end`
hook 里,每完成一天把当前 RunMetrics 部分快照 dump 到磁盘:

```python
def _checkpoint_day(day_idx, run_metrics_partial):
    cp_path = output_dir / f"seed_{seed}_day{day_idx}.partial.json"
    cp_path.write_text(json.dumps(run_metrics_partial.model_dump()))
```

死锁/崩溃发生时至少有部分天的数据,不必从头跑。
